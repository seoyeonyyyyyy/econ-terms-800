## 1. 목적

한국은행 『경제금융용어 800선』을 암기하기 위한 개인용 학습 웹앱.
용어를 훑어보고, 외운 것을 표시하고, 퀴즈로 확인하는 것이 전부다.
다음에 다시 열면 중단 지점부터 이어서 공부할 수 있어야 한다.

## 2. 범위

**포함**
- 789개 용어·정의·연관검색어 데이터화 (표제어 기준, §4.2.1 참조)
- 대분류 4 / 소분류 15 카테고리 부여
- 검색 + 다중 필터 용어장
- 외움 / 안외움 / 중요 체크
- "오늘의 학습" 20장 카드 세션
- OX 퀴즈, 뜻→용어 4지선다 퀴즈
- 진도 통계, 학습 기록 백업 내보내기/불러오기
- PWA (홈 화면 설치, 오프라인 동작)

**제외 (YAGNI)**
- 로그인, 서버, 계정 동기화 — 단, 데이터 구조는 나중에 붙일 수 있게 분리해 둔다
- 간격 반복(SRS) 알고리즘
- 소셜 기능, 랭킹, 공유
- 다국어

## 4. 데이터 파이프라인

### 4.1 텍스트 추출

```bash
pdftotext -enc UTF-8 "2026_경제금융용어 800선.pdf" full.txt
```

`layout` 옵션은 쓰지 않는다. 페이지 경계는 `\f`.

### 4.2 1단계 — 목차에서 용어 화이트리스트 확보

찾아보기(목차)에 표제어가 `용어명·······페이지` 형태로 전부 들어 있다.
이것을 정답지로 삼아야 본문 파싱이 안정된다.

- 패턴: `((?:[^·\n\f]|·(?!··)){2,60}?)\s*·{3,}\s*(\d+)`
- **가운뎃점 주의 (필수)**: 용어명 자체에 `·`가 들어간다 (`동아시아·태평양중앙은행기구`,
  `미국·멕시코·캐나다협정`, `신·재생에너지`). 단순히 `[^·]`로 막으면 이름이 잘린다.
  점선 구분자는 `·`가 3개 이상 연속이므로, **뒤에 `··`가 오지 않는 `·`만** 이름 글자로 허용한다.
- 앞에 붙은 초성 인덱스(`ㄱ`, `ㄴ`) 및 알파벳 섹션 머리글자를 제거
- **줄바꿈된 제목 병합 (필수)**: 제목이 길면 두 줄로 쪼개진다. 실측 6건이다.
  ```
  통화정책 운영체제
  (Monetary Policy Regime)··············· 346
  ```
  점선·페이지번호가 없는 줄은 다음 줄의 제목 앞부분으로 간주해 이어 붙인다.
  꼬리에 붙은 `·` 한 개는 떼어낸다 (`동아시아·태평양중앙은행기구·` → 뒤에 `(EMEAP)`가 붙는다).
- `(EMEAP)`, `일(ASEAN+3)`, `캐나다협정(USMCA)` 같은 파편이 남으면 위 두 규칙 중 하나가 실패한 것이다.

### 4.2.1 "800선"은 실제 항목 수가 아니다

실측 결과 목차 표제어는 **789개**다. 그중 53개가 `간접금융/직접금융`, `단리/복리`처럼
슬래시로 묶여 있고, 이를 모두 풀면 850개가 된다. 800은 어느 쪽도 아니다.

- **묶인 항목은 묶은 채로 한 레코드로 둔다.** 한국은행이 대비 개념을 함께 설명하고,
  정의문도 둘을 같이 다루기 때문에 쪼개면 같은 글이 두 카드에 중복된다.
- 대신 `aliases`에 조각(`["단리", "복리"]`)을 담아 **검색에서 `복리`로도 찾히게** 한다.
- **개수는 느슨하게, 품질은 엄격하게.** 789를 목표로 하되 하한 750만 넘으면 진행한다.
  숫자를 맞추려고 항목을 쪼개거나 합치거나 지어내지 않는다.
  누락은 `build/missing.txt`에 기록만 남긴다.
- 정의 잘림·노이즈 혼입·깨진 연관검색어는 개수와 무관한 별개 문제이며 전부 막는다.

### 4.3 2단계 — 본문에서 정의 추출

- 본문은 목차 뒤부터 시작한다 (첫 용어: `가계부실위험지수(HDRI)`).
- 제거할 노이즈:
  - 페이지 헤더 `I 경제금융용어 800선`
  - 러닝 헤드 — 페이지 첫 줄에 나오는 용어명 (본문이 아님)
  - 단독 숫자 줄 (페이지 번호)
  - 단독 초성 줄 (`ㄱ`, `ㄴ` … 측면 인덱스)
- 용어 경계: 화이트리스트에 있는 이름이 **단독 줄**로 등장하고, 그 위치의 페이지 번호가 목차상 페이지와 ±1 이내일 때만 새 용어의 시작으로 인정한다.
  (본문 중에 다른 용어명이 언급되는 경우가 많아, 페이지 대조 없이는 오탐이 난다.)
- 정의: 용어명 다음 줄부터 다음 용어 시작 전까지.
- `연관검색어 A, B, C` 줄은 정의에서 분리해 `related` 배열로 넣는다.
- **줄 재결합**: 페이지에 따라 한 문단이 한 줄로 나올 때도 있고 줄마다 끊겨 나올 때도 있다.
  줄 끝이 문장 종결부호(`.`, `다`, `)`)가 아니면 다음 줄과 이어 붙인다.
  이어 붙일 때 한글과 한글 사이는 공백 없이 붙이지 말고, 원문의 어절 공백을 보존한다.
- 수식 줄(`가계순저축률(%) = {...} × 100`)은 정의 본문에 그대로 포함한다.

### 4.4 3단계 — 카테고리 분류

각 용어에 `category`(대분류)와 `subcategory`(소분류)를 부여한다.
키워드 규칙으로 1차 분류하고, 점수가 낮거나 경합하는 것만 개별 판단한다.

| 대분류 | 소분류 | 예상 규모 |
|---|---|---|
| 경제상식 | 물가·인플레이션 / 경기·경기지표 / 성장·국민계정 / 재정·조세 / 노동·산업 | ~230 |
| 금융상식 | 통화정책 / 금융시장 / 금융기관·감독 / 금융안정·리스크 / 지급결제·디지털금융 | ~350 |
| 국제·외환 | 외환·환율 / 국제수지·무역 / 국제기구·협정 | ~150 |
| 경영·회계 | 회계·재무 / 기업경영 | ~70 |

- 예상 규모는 키워드 기반 실측 추정치다. ±30% 벗어나면 분류 규칙을 재검토한다.
- 모든 용어는 반드시 하나의 소분류에 속한다. 미분류를 남기지 않는다.
- 판단이 어려우면 **정의문의 첫 문장**을 기준으로 삼는다.

### 4.5 산출물

`terms.json` — 배열, 789개.

```json
{
  "id": "기준금리",
  "term": "기준금리",
  "alt": "Base Rate",
  "aliases": [],
  "chosung": "ㄱㅈㄱㄹ",
  "def": "한국은행이 금융기관과 환매조건부증권 매매 등 거래를 할 때 기준이 되는 금리로 ...",
  "related": ["콜금리", "공개시장운영"],
  "category": "금융상식",
  "subcategory": "통화정책",
  "page": 137
}
```

- `id`: 용어명 그대로. 중복 시 뒤에 `#2` 부여
- `alt`: 정의문 첫머리의 괄호 안 영문명. 없으면 `null`
- `aliases`: 슬래시로 묶인 표제어의 조각. `"단리/복리"` → `["단리", "복리"]`.
  묶음이 아니면 빈 배열. **검색에만 쓰고 레코드를 쪼개지 않는다.**
- `chosung`: 초성 검색·힌트용. 한글만 추출해 초성 변환
- `related`: 화이트리스트에 존재하는 것만 남긴다 (오타·페이지 잘림 방어)

## 5. 저장소 설계

`localStorage` 키 3개로 분리한다. 용어 데이터와 학습 기록을 섞지 않는다.

```js
// econ.progress — 학습 기록. 나중에 서버로 그대로 올릴 수 있는 형태
{
  "기준금리": { "status": "known", "starred": true, "seen": 4, "wrong": 1, "at": 1758000000000 }
}
// status: "known" | "unknown" | null(미학습)

// econ.session — 진행 중인 학습 세션 (중단 후 이어하기)
{ "ids": ["기준금리", ...], "cursor": 7, "startedAt": 1758000000000 }

// econ.prefs — 마지막 필터, 마지막 화면
{ "lastView": "list", "filters": { "category": "금융상식", "status": "unknown" } }
```

**원칙**
- 쓰기는 `store.js`를 통해서만 한다. 다른 파일이 `localStorage`를 직접 건드리지 않는다.
- 모든 읽기·쓰기를 `try/catch`로 감싼다. 사생활 보호 모드에서 예외가 날 수 있다.
- 저장 실패해도 앱은 정상 동작해야 한다 (기록만 유실).
- **백업**: 설정 화면에 내보내기/불러오기 버튼. `econ-backup-YYYYMMDD.json` 파일로 저장·복원.
  불러오기는 병합이 아니라 덮어쓰기이며, 실행 전에 확인을 받는다.
- 용어 데이터가 갱신되어 `terms.json`에 없는 id가 기록에 남아도 무시하고 넘어간다 (오류 아님).

## 6. 화면 사양

### 6.1 홈

- 전체 진도 바 (`known` 수 / 789)
- 대분류 4개의 진도를 각각 막대로 표시
- `[오늘의 학습 20개 시작]` — 진행 중 세션이 있으면 `[이어하기 (7/20)]`로 바뀐다
- 하단 진입: `용어장` `OX 퀴즈` `용어 맞히기` `통계`

### 6.2 용어장

- 검색: 용어명·영문명·초성·`aliases` 매칭. 정의문 본문 검색도 포함
  (`복리`로 검색하면 `단리/복리` 카드가 나와야 한다)
- 필터 (모두 조합 가능, AND)
  - 대분류 4 / 소분류 15
  - 상태: 전체 / 외움 / 안외움 / 미학습
  - 중요 표시만 보기
  - 초성 ㄱ~ㅎ, A~Z
- 현재 필터에 걸린 개수를 항상 표시한다
- 목록 항목: 용어명 + 소분류 + 외움 토글 + 중요 토글 (목록에서 바로 체크 가능해야 한다)
- 789개를 한 번에 그리면 느리다. 가상 스크롤 또는 50개씩 증분 렌더링.
- 상세: 용어명 / 영문명 / 소분류 / 정의 전문 / 연관검색어(탭하면 해당 용어로 이동) / 외움·중요 토글

### 6.3 학습 세션

- 대상: `status != "known"`인 용어 중 20개. 미학습 → 안외움 순으로 채운다
- 현재 필터가 걸려 있으면 그 범위 안에서 뽑는다
- 카드: 용어명만 표시 → `[뜻 보기]` → 정의 표시 → `[모르겠음]` / `[외웠음]`
- 진행 표시 `7/20`. 중단해도 `econ.session`에 저장되어 이어할 수 있다
- 20장을 마치면 그 20개로 복습 퀴즈(OX 10 + 4지선다 10)로 바로 연결

### 6.4 OX 퀴즈

- 범위 선택: 전체 / 대분류 / 소분류 / 안외운 것만 / 중요만
- 문항 수: 10 / 20 / 무한
- 오답이면 해설과 함께 원문을 보여주고, `[이 용어 보기]`로 상세 이동
- 오답 용어는 `wrong` 카운트를 올린다. **`status`는 자동으로 바꾸지 않는다.**
  외움/안외움은 사용자가 직접 정하는 값이고, 퀴즈가 말없이 뒤집으면 체크한 의미가 사라진다.
  대신 `known`인데 틀린 경우 결과 화면에 `[안외움으로 되돌리기]` 버튼을 띄워 사용자가 선택하게 한다.

### 6.5 용어 맞히기 (4지선다)

- 정의를 보여주고 용어 4개 중 고르게 한다
- **정의문에 정답 용어명이 그대로 등장하면 반드시 `○○○`으로 마스킹한다.** 이걸 빠뜨리면 문제가 성립하지 않는다.
  영문명·약어도 같이 마스킹한다.
- 오답 보기 3개는 **같은 `subcategory`에서** 뽑는다. 같은 소분류에 4개 미만이면 같은 `category`로 넓힌다.
- 힌트 버튼: 초성 공개 (`ㄱㅈㄱㄹ`)

### 6.6 출처 표기 (전 화면 공통)

앱을 외부에 공개 배포하므로 모든 화면 하단에 다음을 고정 노출한다.

```
자료 출처: 한국은행 『경제금융용어 800선』(2026)
```

용어 상세 화면에는 원본 쪽수도 함께 표시한다 (`terms.json`의 `page`).

### 6.7 통계

- 대분류·소분류별 진도
- 누적 퀴즈 정답률
- 자주 틀린 용어 Top 20 (`wrong` 내림차순) → 탭하면 해당 용어로 이동
- 백업 내보내기 / 불러오기 / 전체 초기화

## 7. 퀴즈 생성 알고리즘

### 7.1 OX 문항 — 규칙 3종

정의문에서 길이 30~120자의 문장 하나를 고른다. 첫 문장은 보통 정의라서 우선 사용한다.

**규칙 1 — 반의어 치환 (주력)**

문장에 아래 쌍 중 하나가 있으면 뒤집어 거짓 문항을 만든다.

```
상승↔하락  증가↔감소  확대↔축소  완화↔긴축  인상↔인하
매입↔매각  흑자↔적자  상향↔하향  강화↔약화  호황↔불황
초과↔미달  유입↔유출

# 부분 문자열 오치환을 막으려면 어미까지 붙여야 한다 ("높이"가 "낮이"가 되면 안 된다)
높아↔낮아  높은↔낮은  높다↔낮다  커지↔작아지  늘어↔줄어
```

```
원문: "기준금리를 인상하면 시중금리는 상승 압력을 받는다"
거짓: "기준금리를 인상하면 시중금리는 하락 압력을 받는다"
해설: "원문은 '상승'입니다."
```

한 문장에 여러 쌍이 있으면 **하나만** 바꾼다. 둘 이상 바꾸면 문장이 무너진다.

**규칙 2 — 숫자 교란**

문장의 숫자를 다른 값으로 바꾼다. `연 8회 → 연 12회`, `40% → 60%`, `3개월 → 6개월`.
- 연도(`2018년`)와 법령·기구 이름에 붙은 숫자(`바젤 III`, `G20`)는 건드리지 않는다.
- 바꾼 값이 원래 값과 너무 가까우면(±10% 이내) 다시 뽑는다.

**규칙 3 — 유사 용어 교차**

다른 용어의 정의를 붙여 거짓 문항을 만든다. 단, **무작위로 고르지 않는다.**
우선순위: ① `related`로 연결된 용어 → ② 같은 `subcategory` → ③ 같은 `category`.
연결이 전혀 없으면 이 규칙을 쓰지 않는다.

**공통**
- 참 문항은 원문을 그대로 쓴다 (마침표·어미만 정리)
- 참:거짓 비율은 대략 50:50
- 어떤 규칙도 적용할 수 없는 용어는 OX 출제 대상에서 제외한다. 억지로 만들지 않는다.
- 규칙 1·2가 가능하면 규칙 3보다 우선한다. 변별력이 더 높다.

### 7.2 알려진 한계

규칙 기반이라 "몰라도 티 나는" 문항이 일부 섞인다.
검수에서 표본 30문항을 확인해 그 비율이 30%를 넘으면 규칙 1·2의 적용 범위를 넓히는 쪽으로 조정한다.

## 9. 검증 기준

`tools/verify.py`가 전부 통과해야 완료로 본다.

**데이터**
- [ ] 용어 수가 750 이상 (789 목표, 딱 맞출 필요 없음)
- [ ] `id` 중복 없음
- [ ] 모든 `def`가 50자 이상
- [ ] `def`에 `경제금융용어 800선`, 단독 숫자 줄, 단독 초성 줄이 섞이지 않음
- [ ] `def`가 조사나 어미 중간에서 끊기지 않음 — 마지막 글자가 `.` `다` `)` `%` 또는 숫자
      (수식으로 끝나는 항목이 있다: `... × 100`)
- [ ] 모든 `related` 항목이 실제 존재하는 `id`
- [ ] 모든 용어에 `category`·`subcategory`가 있고, 정의된 4/15 값 중 하나
- [ ] 무작위 30개를 PDF 원문과 사람이 대조 (Claude 담당)

**앱**
- [ ] 필터 4종을 동시에 걸어도 개수와 목록이 일치
- [ ] 외움 체크 후 새로고침해도 유지
- [ ] 세션 중단 후 다시 들어가면 같은 지점에서 이어짐
- [ ] 4지선다에서 정답 용어명이 문제에 노출되지 않음 (표본 20문항)
- [ ] OX 표본 30문항 중 "몰라도 맞히는" 문항이 30% 이하 (Claude 담당)
- [ ] localStorage를 막아도 앱이 죽지 않음
- [ ] 폰 화면 폭 360px에서 가로 스크롤이 생기지 않음
- [ ] 백업 내보내기 → 초기화 → 불러오기로 기록이 복원됨
- [ ] 모든 화면 하단에 출처 표기가 고정 노출됨

## 10. 역할 분담

**Claude (총괄)**
1. 본 명세 작성·관리
2. 파싱 결과 검수 — 개수, 잘림, 노이즈 혼입, 무작위 30개 원문 대조

5. Artifact 발행 및 링크 전달

데이터가 틀리면 그 위에 쌓은 것이 전부 무의미해진다.
